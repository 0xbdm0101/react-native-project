# Quickstart: 扫码功能 (QR Code Scanner)

**Date**: 2026-07-08

## Prerequisites

- 开发环境已配置（Node.js、Expo CLI、iOS Simulator / Android Emulator 或真机）
- 真机测试必需（模拟器无摄像头硬件，无法测试扫码）
- 已安装依赖：`npx expo install expo-camera expo-clipboard`

## 验证场景

### 场景 1: 权限流程 — 首次使用

1. 在首页点击「扫码」入口
2. 系统弹出相机权限请求对话框
3. 点击「允许」→ 进入扫码页面，摄像头预览正常显示
4. 点击「拒绝」→ 显示权限引导页面，包含"去设置"按钮

**Expected**: 权限流程完整，无崩溃或空白页

### 场景 2: 扫描二维码 — URL 类型

1. 打开扫码页面，对准一个包含 `https://example.com` 的二维码
2. 摄像头画面中二维码被取景框包围
3. 识别成功后，取景框变绿高亮，结果面板从底部弹出
4. 结果面板显示：URL 内容、码制类型（QR 码）、识别时间
5. 点击「打开链接」→ 在应用内浏览器打开该 URL
6. 点击「复制」→ Toast 提示"已复制"，剪贴板内容为 URL

**Expected**: 从对准到识别 < 1 秒，三个操作按钮均可正常使用

### 场景 3: 扫描条形码 — 商品条码

1. 打开扫码页面，对准一个 EAN-13 商品条形码（如 6901234567890）
2. 识别成功后，结果面板显示 13 位数字
3. 「打开链接」按钮不可见（内容非 URL）
4. 点击「分享」→ 调起系统分享面板

**Expected**: 条形码识别准确，数字完整无遗漏

### 场景 4: 闪光灯 — 弱光环境

1. 在光线较暗的环境下打开扫码页面
2. 点击闪光灯按钮（⚡图标）
3. 闪光灯开启，摄像头画面变亮
4. 再次点击关闭闪光灯

**Expected**: 闪光灯开关即时响应，开启后暗光下识别成功率明显提升

### 场景 5: 相机不可用

1. 模拟摄像头被占用或不可用（可在模拟器中测试）
2. 系统显示错误提示"摄像头不可用"
3. 提供「返回」按钮返回上一页

**Expected**: 明确的错误提示，不出现白屏或崩溃

### 场景 6: 连续扫描

1. 打开扫码页面，扫描第一个二维码 → 结果显示
2. 将摄像头移向第二个不同的二维码 → 结果更新为新内容
3. 将摄像头从所有码上移开 → 最后一次结果保持显示

**Expected**: 结果实时更新，无闪烁或混乱

### 场景 7: 页面生命周期

1. 在扫码页面中按 Home 键回到桌面 → 摄像头暂停
2. 重新打开应用回到扫码页面 → 摄像头自动恢复
3. 按返回键退出扫码页面 → 摄像头资源释放（无后台耗电）

**Expected**: 页面切换不影响应用稳定性，无内存泄漏
