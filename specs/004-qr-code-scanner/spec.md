# Feature Specification: 扫码功能 (QR Code Scanner)

**Feature Branch**: `004-qr-code-scanner`

**Created**: 2026-07-08

**Status**: Draft

**Input**: User description: "用户可以通过摄像头实时扫描二维码和条形码，解析内容后展示结果，并支持将扫码结果复制、分享或直接使用"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 实时扫描二维码 (Priority: P1)

用户打开扫码页面，将摄像头对准二维码，系统实时识别并解析二维码内容，将结果显示在屏幕上。用户可以复制解析结果到剪贴板。

**Why this priority**: 二维码扫描是扫码功能的核心价值，覆盖 90% 以上的使用场景，是 MVP 必须实现的基线能力。

**Independent Test**: 用户打开扫码页面，对准任意二维码（如网址、文本），系统应在 1 秒内识别并展示结果，点击复制按钮可将内容复制到剪贴板。

**Acceptance Scenarios**:

1. **Given** 用户已授权相机权限且打开扫码页面，**When** 用户将摄像头对准一个包含 URL 的二维码，**Then** 系统在取景框内高亮识别区域，并在 1 秒内将 URL 内容展示在结果区域
2. **Given** 扫码页面已打开且摄像头正常工作，**When** 用户将摄像头对准一个包含纯文本的二维码，**Then** 系统正确解析并展示完整文本内容
3. **Given** 扫码结果已展示在屏幕上，**When** 用户点击"复制"按钮，**Then** 扫码结果被复制到系统剪贴板，并显示"已复制"的视觉反馈
4. **Given** 用户正在扫码页面，**When** 用户将摄像头从二维码移开，**Then** 上一次的扫码结果仍然保留在屏幕上，方便用户查看

---

### User Story 2 - 条形码扫描 (Priority: P2)

用户打开扫码页面，将摄像头对准商品条形码（一维码），系统实时识别条形码并解析其数字编码，展示结果。

**Why this priority**: 条形码是零售和物流场景的核心码制，扩展了扫码功能的使用范围，但不影响二维码的核心价值。

**Independent Test**: 用户打开扫码页面，对准任意商品条形码（如 EAN-13、Code-128），系统应在 1 秒内识别并展示条码数字。

**Acceptance Scenarios**:

1. **Given** 用户已打开扫码页面，**When** 用户将摄像头对准一个 EAN-13 商品条形码，**Then** 系统识别并展示 13 位数字编码
2. **Given** 用户已打开扫码页面，**When** 用户将摄像头对准一个 Code-128 条形码，**Then** 系统正确解析并展示条码内容
3. **Given** 扫码结果已展示，**When** 结果是纯数字的条形码内容，**Then** 用户仍可正常复制、分享该结果

---

### User Story 3 - 结果分享与使用 (Priority: P3)

用户在获得扫码结果后，可以通过系统分享面板将结果分享给其他应用（如微信、短信、备忘录），也可以直接"使用"结果——如果结果是 URL，可直接在浏览器中打开；如果是文本，可跳转到对应处理页面。

**Why this priority**: 分享和使用是扫码后的增值操作，提升用户体验闭环，但属于增强功能，不影响核心扫描能力。

**Independent Test**: 扫码得到 URL 结果后，点击"打开链接"按钮，系统在应用内浏览器打开该链接；点击"分享"按钮，调起系统分享面板。

**Acceptance Scenarios**:

1. **Given** 扫码结果为 URL，**When** 用户点击"打开链接"按钮，**Then** 系统在应用内浏览器中打开该 URL
2. **Given** 扫码结果为任意内容，**When** 用户点击"分享"按钮，**Then** 系统调起原生分享面板，用户可选择分享目标
3. **Given** 扫码结果为文本（非 URL），**When** 结果显示在屏幕上，**Then** "打开链接"按钮不可见或置灰，仅显示复制和分享选项
4. **Given** 扫码结果包含特殊协议链接（如 `wifi://`、`tel:`），**When** 用户点击"使用"按钮，**Then** 系统根据协议类型执行对应操作或提示用户

---

### Edge Cases

- 用户在光线极暗的环境下扫描，摄像头画面噪点严重时，系统如何处理？（应提示"光线不足，请开启闪光灯"并提供闪光灯开关）
- 用户扫描的是损坏/模糊/不完整的二维码，系统如何反馈？（应在超时后提示"未识别到二维码，请调整角度或距离"）
- 用户未授权相机权限时，进入扫码页面会发生什么？（应显示权限引导页面，告知用户如何开启权限）
- 用户扫描的二维码内容为空字符串，系统如何处理？（应提示"二维码内容为空"）
- 用户快速连续扫描多个不同的码，结果应如何更新？（应实时更新为最新扫描结果，避免结果混乱）
- 扫码过程中有电话或通知中断，恢复后摄像头状态如何？（应自动恢复扫描状态）
- 设备不支持摄像头或摄像头被占用时如何处理？（应提示"摄像头不可用"）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须支持通过后置摄像头实时识别二维码（QR Code），包括 URL、纯文本、数字等常见内容类型
- **FR-002**: 系统必须支持通过后置摄像头实时识别常见一维条形码（EAN-13、EAN-8、Code-128、Code-39、UPC-A、UPC-E），并解析其数字/字符编码
- **FR-003**: 系统必须在摄像头预览画面上叠加取景框，引导用户对准扫码目标
- **FR-004**: 系统必须在成功识别后，在取景框内高亮标记识别到的码区域
- **FR-005**: 系统必须在识别成功后，将扫码结果以文本形式展示在屏幕底部或取景框下方
- **FR-006**: 用户必须能够将扫码结果复制到系统剪贴板，并在复制成功后获得视觉反馈
- **FR-007**: 用户必须能够通过系统原生分享面板将扫码结果分享给其他应用
- **FR-008**: 当扫码结果为 URL 时，用户必须能够点击按钮在应用内浏览器中打开该链接
- **FR-009**: 系统必须在首次使用时请求相机权限，并在权限被拒绝时显示引导说明
- **FR-010**: 系统必须提供闪光灯（手电筒）开关，允许用户在暗光环境下开启补光
- **FR-011**: 系统必须在摄像头不可用时（被占用、不存在、硬件故障）向用户展示明确的错误提示
- **FR-012**: 系统必须在连续扫描模式下保持上一次结果可见，直到新的识别结果覆盖

### Key Entities

- **ScanResult（扫码结果）**: 代表一次扫码识别的内容，包含原始文本内容、内容类型（URL/文本/数字/其他）、识别时间戳、码制类型（QR Code / EAN-13 / Code-128 等）
- **CameraState（相机状态）**: 代表当前相机的工作状态，包含权限状态（未请求/已授权/已拒绝）、闪光灯状态（开/关）、摄像头可用性（可用/占用/不可用）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在正常光照条件下，用户对准二维码到识别成功的平均时间不超过 1 秒
- **SC-002**: 系统支持至少 6 种常见码制（QR Code、EAN-13、EAN-8、Code-128、Code-39、UPC-A）
- **SC-003**: 用户在首次使用扫码功能时，从打开页面到成功识别第一个码的完成率达到 95% 以上
- **SC-004**: 扫码识别准确率在正常条件下达到 98% 以上（不含损坏/模糊的码）
- **SC-005**: 用户完成"扫码 → 复制结果"的完整操作流程不超过 5 秒
- **SC-006**: 相机权限被拒绝后，100% 的用户能看到明确的权限引导说明，而非空白页面或崩溃
- **SC-007**: 在低光照环境下开启闪光灯后，识别成功率提升至正常光照水平的 80% 以上

## Assumptions

- 用户设备具有后置摄像头且支持自动对焦（绝大多数智能手机均满足）
- 目标用户群体为中国区用户，主要扫描场景包括：网址链接、支付码、商品条码、WiFi 配置码
- 扫码功能作为独立页面存在，可通过首页功能入口或底部导航进入
- 应用已具备应用内浏览器（WebView）能力，可直接复用打开 URL 结果
- 相机权限请求遵循 iOS/Android 平台标准流程，应用需在 Info.plist / AndroidManifest 中声明相机使用说明
- 扫码识别依赖设备本地计算能力，不需要网络连接
